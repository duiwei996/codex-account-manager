# Codex 账号管理器

用于管理多个 Codex 账号的桌面应用，支持 Windows、macOS 和 Linux。

[English](README.en.md) · [下载安装包](https://github.com/duiwei996/codex-account-manager/releases)

## 功能介绍

- 添加和登录账号，导入已有账号，重命名、隐藏或删除账号。
- 在主窗口或系统托盘切换账号，查看订阅、额度和用量。
- 单个或全部导出账号，支持官方 auth.json 与 CPA 格式，支持批量导入和中英文界面。
- 检查新版本，确认后下载并安装更新。
- WebDAV 同步账号与系统设置，可独立选择同步内容，支持浏览服务器目录和自动同步。

## 安装

打开[版本下载页面](https://github.com/duiwei996/codex-account-manager/releases)，选择适合电脑的安装包：

| 系统 | 安装包与安装方式 |
| --- | --- |
| Windows | 下载 `setup.exe`，双击并按提示安装。 |
| macOS | 下载 `.dmg`，打开后将应用拖入“应用程序”。Apple 芯片选择 `aarch64`，Intel 芯片选择 `x64`。 |
| Linux | 下载 `.AppImage` 并赋予执行权限后运行，或通过系统软件安装工具安装 `.deb` / `.rpm`。 |

若出现系统安全提示，请核对安装包来自本仓库的版本下载页面。

macOS 安装包使用免费临时签名（Ad-hoc），未经 Apple 公证。首次打开若提示“Apple 无法验证此应用是否包含恶意软件”，确认安装包来自本仓库后，按以下步骤放行：

1. 点击提示中的“完成”。
2. 打开“系统设置 → 隐私与安全性”，向下找到该应用的拦截提示，点击“仍要打开”。
3. 按系统提示确认，再点击“打开”。系统会保存该应用的放行设置。

## 使用

1. 打开应用，点击添加账号，通过浏览器登录，或导入已有的 `auth.json`。
2. 在账号列表查看账号信息，选择需要使用的账号并切换。
3. 需要时，也可以通过系统托盘切换账号。
4. 点击顶部文件夹双向箭头图标，在“导入 / 导出”弹窗的两个标签中切换。支持多文件批量导入；导出可筛选分类和账号状态，默认全部分类、有效账号，两个筛选下拉均将“全部”放在首项。账号卡片保留单账号导出，可选择官方 auth.json 或 CPA 格式。
5. 收到新版本提示后，确认安装并按提示重启应用。
6. 右侧齿轮打开设置，分为常规、账号与自动化、更新与关于。开机自启及自启时最小化到托盘默认开启；自动刷新默认每分钟刷新当前分类及正在使用的账号，也可选仅当前账号，后台间隔为前台的 5 倍。失效账号不参与刷新。刷新间隔、预热开关和时间共用一套设置，不按分类分别保存。

顶部刷新、自动预热和定时预热均处理当前分类及正在使用的账号，去重并跳过失效账号；选中“全部”分类时才覆盖全部非风控有效账号。切换分类后，后续预热请求按新范围检查。定时预热的已添加时间显示为标签，点击铅笔图标在弹窗中编辑；每天按本地时间执行，应用未运行时错过的时间不会补执行。自动预热在额度周期开始后的约 5 分钟内触发，同一周期最多一次；两种方式执行前均核对实时额度。

托盘固定采用当前使用账号的小时及每周剩余额度模式，不提供显示模式设置；旧的隐藏配置不再生效。macOS 菜单栏显示额度文字，Windows 保留托盘图标和点击后的额度面板。

启动时先恢复上次成功获取的账号信息、额度和使用统计，再在后台刷新；缺少缓存的账号会补查一次，授权过期或请求失败时保留已有数据。

JSON 文件含有完整登录凭据，请妥善保管，不要公开分享。CPA Codex 格式适用于登录账号，API Key 账号使用官方格式。可选预热功能可能消耗账号额度。

### WebDAV 同步

在设置的“WebDAV 同步”中填写服务器地址、用户名和密码，点击“选择目录”浏览 WebDAV 文件夹，再选择当前目录；也可手动输入相对服务器地址的目录。目录须已存在。“测试连接”检查登录和目录读取，实际写入权限在同步时核对。WebDAV 密码保存在本机系统凭据库。

“同步账号”和“同步系统设置”可独立开启。账号同步包含登录凭据、名称、邮箱、订阅类型、风控与隐藏状态，以及订阅到期时间、额度、积分和重置次数缓存。风控账号也参与同步。各电脑独立选择当前账号；设置同步包含语言、外观、刷新、切换方式、预热和更新检查。开机启动、窗口、本机路径、WebDAV 配置及累计使用统计留在本机。

每台电脑记录上次成功同步的云端版本。云端版本未变化时，将本地所选内容上传；云端变化或首次双方数据不同时，弹窗选择「使用本地」「使用云端」或「取消」。选择后整份替换所选同步内容，包括新增、修改和删除，不做字段合并；内容相同时直接建立同步记录。账号自动刷新及缓存更新也参与同步。

主页云端图标提供「立即同步」，成功和失败均有提示。设置中另外提供「本地覆盖云端」「云端覆盖本地」，确认覆盖方向后执行。同步不生成额外的恢复副本；历史副本不会自动删除。云端缺少所选内容时停止下载，不清空本机。

自动同步在启动后检查一次，之后默认每 30 分钟检查，可设置为 1–1440 分钟。等待选择时暂停；取消后点击「立即同步」可重新检查。连接失败在下一轮重试。上传以强 ETag 校验云端版本，避免覆盖检查后另一设备刚写入的数据；本机保存加密的最近成功同步基线。

云端保存 `accounts.sync.gz` 压缩文件，不额外加密，包含所选账号的完整登录凭据，请使用可信存储和 HTTPS。

同步不会自动切换账号或改写当前 CLI 的 `auth.json`。多机同时使用相同登录凭据仍可能遇到刷新令牌轮换冲突，必要时重新登录。

分类「免费」「团队」用于普通账号；移入「风控」后不显示在全部及原分类，不参与普通分类刷新、导出和预热。移出风控后恢复原分类。

更新内容见 [更新记录](CHANGELOG.md)。

## 本地构建

使用 `.node-version` 指定的 Node.js 版本、`package.json` 指定的 pnpm 和 `rust-toolchain.toml` 指定的 Rust，安装对应平台的 Tauri 构建环境及 `cargo-audit 0.22.1` 后，运行 `pnpm build:local`。入口先执行与 CI 共用的完整检查，全部通过后生成支持自动更新的本地安装包；检查失败即停止打包。该入口使用 `src-tauri/updater-public-key.txt` 中的正式公钥，以及本仓库 GitHub Releases 的更新地址；前后端更新功能同时启用。可通过 `TAURI_UPDATER_PUBLIC_KEY` 显式提供公钥，必须与正式更新包的签名匹配。

本地包接收正式更新不需要私钥，也不生成签名更新产物。发布供其他安装接收的更新仍通过正式发布流程签名并上传。普通 `pnpm build` 仅构建前端；直接运行 Tauri 构建命令不会自动启用更新。

Windows 的 `build:local` 会在官方安装器外生成项目自有安装入口：先检查版本和原安装目录，再执行覆盖升级；快捷方式逻辑使用 Tauri 官方安装钩子，不修改第三方源码或模板。正式发布流程会对最终 EXE 重新签名。Windows 自动更新分别提供 EXE 和 MSI 入口，保留全部平台安装格式。

## 版本管理

`pnpm install` 会为当前仓库安装推送前检查，也可运行 `pnpm hooks:install`。每次正常 `git push` 都重新执行两端依赖安全审计、工具链、版本与 Rust 格式检查；前端高危及严重漏洞阻止推送，低危及中危保留报告；Rust 保持现有审计标准。审计服务失败或工具缺失也阻止推送。检查要求工作区干净且推送当前 HEAD，避免审计工作区却推送另一份代码。已有其他 Git hooks 配置时安装会停止，须先整合。工具链或显式指定的 `CARGO_AUDIT_BIN` 路径变化后重新安装 hooks；CI 不安装本地 hooks。不要用 `--no-verify` 跳过检查。检查通过只覆盖当时已知公告，云端继续保留独立审计。

根目录 `VERSION` 是唯一版本来源。本地构建不会自动加号；云端构建读取相同版本，已存在的版本会跳过发布，低于已有版本则报错。

修改 `VERSION` 后运行 `pnpm version:sync` 同步前端、Tauri 和 Cargo；也可通过 `pnpm version:bump 1.0.5` 明确更新所有版本文件。`pnpm version:check` 和构建入口会检查一致性。正式发布前确认目标版本尚未使用；已预留的草稿也视为已使用，不覆盖原有产物。

推送前运行 `pnpm check:ci`，核对工具链、版本、冻结锁文件安装、Rust 格式、前后端依赖安全审计、前端编译及测试、当前系统的 Rust 测试；任一检查失败即停止。CI 的 `pnpm check:frontend` 和 `pnpm check:rust` 复用同一检查脚本，`pnpm build:local` 强制执行完整检查。审计从官方源读取当前漏洞库，过去通过的锁文件也须重新检查；官方预编译审计器可通过 `CARGO_AUDIT_BIN` 指定路径。仅需格式和安全审计时可运行 `pnpm release:preflight`。本地检查不替代云端其他系统、签名和发布产物的验收。更新插件关闭旧版 ZIP 解包支持；本项目使用原始 EXE/MSI、AppImage 和 macOS tar.gz 更新包。
